Getting started

  1. Open Jira settings → Apps → Attachment Policy Guard. You need Jira administrator permission.
  2. The app starts in report mode: nothing is removed. Review the default policy (executables, scripts and disk images are blocked) and adjust it.
  3. Use Test a file to check a sample file against your unsaved policy.
  4. Watch the audit log for a few days. When it only shows files you really want removed, switch to enforce mode.

When you write to us

  • Your site URL (yoursite.atlassian.net)
  • The work item key and roughly when the file was attached
  • The audit log row (Result and Reason), or a note that no row appeared
  • Whether the app was in report mode or enforce mode

Please do not send the file itself unless we ask for it.

Known limits

  • Jira does not let apps block an upload before it happens. In enforce mode the file is removed within seconds after upload. Notification emails sent in that window may still mention the file.
  • Removed attachments cannot be restored by the app. Start in report mode.
  • Only attachments added after the app is installed are checked. Existing attachments are never touched.
  • The app reads the first 4 KB of each new attachment to identify its type. It is not antivirus software.
  • If the content cannot be read, the file is kept and flagged in the audit log, unless you choose to treat such files as blocked.
  • The audit log keeps policy matches for 90 days. CSV export includes up to 5,000 entries.

Updates

Releases are published through the Atlassian Marketplace with release notes. Minor updates install automatically; an update that requires new permissions needs a Jira administrator to approve it.
